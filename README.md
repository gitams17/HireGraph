# HireFlow AI — Phase 1 Foundation

A monorepo foundation for the HireFlow AI recruitment workflow platform.

## Phase 1 scope

- Next.js + TypeScript frontend (generated locally by the setup script).
- Django + Django REST Framework backend.
- PostgreSQL 17 for persistent application data.
- Redis 7.4 as a local supporting service for later asynchronous work.
- Local environment configuration and Git initialisation.
- A database-aware backend health endpoint.

This is a development foundation, not the complete application. Authentication, hiring models, LangGraph orchestration, Celery workers and product UI are added in later phases.

## Prerequisites on Windows

Install these before setup:

1. Python 3.13.x — https://www.python.org/downloads/windows/
2. Node.js 26 LTS — https://nodejs.org/
3. Git for Windows — https://git-scm.com/download/win
4. Docker Desktop with the WSL 2 backend — https://www.docker.com/products/docker-desktop/

Open a new PowerShell window after installation and verify:

```powershell
py -3.13 --version
node --version
npm --version
git --version
docker --version
docker compose version
```

## 1. Extract and enter the repository

Extract the ZIP, open PowerShell in the extracted `hireflow-ai-phase1` folder, and keep that folder as the repository root.

## 2. Run the setup script

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\scripts\setup-phase1.ps1
```

The script:

- Creates `.env` from `.env.example` if it does not exist.
- Creates a Python virtual environment at `.venv`.
- Installs the pinned Django/DRF dependencies.
- Generates `frontend/` with the official Next.js 16.4.6 CLI using its default TypeScript, Tailwind CSS and App Router setup.
- Creates `frontend/.env.local` for the local API base URL.
- Initialises a local Git repository if one does not already exist.

Review `.env` and change the example local passwords before starting the services. Do not commit `.env` or `frontend/.env.local`.

## 3. Start PostgreSQL and Redis

Start Docker Desktop, wait until it reports that the engine is running, and execute:

```powershell
.\scripts\start-infra.ps1
```

Equivalent command:

```powershell
docker compose up -d db redis
docker compose ps
```

Both database services bind to `127.0.0.1` only. Persistent data is stored in Docker volumes.

To stop the services without deleting their data:

```powershell
docker compose down
```

Do not use `docker compose down -v` unless you intend to delete the local database and Redis volumes.

## 4. Run Django

In PowerShell terminal 1, from the repository root:

```powershell
.\.venv\Scripts\Activate.ps1
Set-Location backend
python manage.py check
python manage.py migrate
python manage.py runserver 8000
```

Open http://localhost:8000/api/health/ . Expected response after PostgreSQL is ready:

```json
{"status":"ok","database":"connected"}
```

Create an admin account when needed:

```powershell
python manage.py createsuperuser
```

Django admin: http://localhost:8000/admin/

## 5. Run Next.js

In PowerShell terminal 2, from the repository root:

```powershell
Set-Location frontend
npm run dev
```

Open http://localhost:3000 .

The frontend API base URL is in `frontend/.env.local`. It is a public URL, not a secret.

## 6. Initial Git commit

After reviewing the generated files and `.env.example`:

```powershell
git status
git add .
git commit -m "chore: initialize HireFlow AI foundation"
```

Create the remote GitHub repository through GitHub, then add its remote URL:

```powershell
git remote add origin https://github.com/<your-github-username>/hireflow-ai.git
git branch -M main
git push -u origin main
```

Replace the placeholder with the repository URL created in your GitHub account. Do not put credentials or tokens into the remote URL.

## Troubleshooting

### `py -3.13` cannot find Python

Install Python 3.13 and enable the Python Launcher during installation. Reopen PowerShell.

### `docker compose` cannot connect

Start Docker Desktop and wait for the Docker engine to finish starting. Then reopen PowerShell and retry.

### PostgreSQL port 5432 is already in use

Stop the other local PostgreSQL service or change the host-side port mapping in `docker-compose.yml` and set `POSTGRES_PORT` in `.env` to the same host port.

### Django cannot connect to PostgreSQL

Check `docker compose ps`, then compare `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_HOST` and `POSTGRES_PORT` in `.env` with the Compose configuration. The local Django process uses `127.0.0.1`; a future Django container would use the Compose service name `db`.

### Next.js cannot reach Django

The API endpoint is not yet integrated into the generated starter UI. The configured base URL is `http://localhost:8000`; CORS is enabled for the local Next.js origin in Django settings. The actual API client is added in a later phase.
